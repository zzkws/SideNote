# PDF 阅读上下文与回答风格

## 当前实现

PDF.js 文字项 → 识别栏与跨栏行 → 分离图表说明 → 合并正文行和跨页断词 → 建立原始字符到规范正文的偏移映射 → 从同一份正文读取选区、句子、前后文。

- 保留语义段落，排版换行转为空格；行尾断词合并，常见英文连字展开。
- 图注独立存放，按页码作为补充上下文发送；避免打断正文中跨栏、跨页的句子。选中图注时，正文上下文截到当前图注页。
- PDF 查询直接传入精确正文偏移，避免靠段落字符串回查位置。图注查询使用当前页的正文边界。
- 正常查询发送文章开头至选区结束后 1000 字符，末尾尽量扩展到句/段边界。不是每次发送整篇论文的后续章节。
- 160000 字符的既有上下文阈值仍保留；超过时发送开头 12000 字符和选区附近内容，并带省略标记。
- 文本抽取是版面启发式处理，不宣称任意 PDF 都能完美恢复。扫描件仍没有可划选的文字层；公式上下标、分式和复杂表格需结合页图核对。

## 原文图像

带页图的 Flash 调用使用官方视觉型号 `deepseek-v4-flash-vision-exp`，以 `user.content` 中的 `image_url` 块传入 JPEG 页图；不带图的普通查询仍使用设置中的 `deepseek-v4-flash`。

使用当前页，以及当前页之前有可识别图表说明的页面，去重后最多取最近 12 页。每页长边约 1800 像素，JPEG 质量 0.88，图片按页码排列并标注来源。当前页图像可能包含尚未读到的下半页，提示词明确限制回答仍围绕选区。没有图表说明的早期图片页暂不自动收集。

页面由 PDF.js 独立画布生成，完整保留矢量图、表格和图注；不依赖滚动位置、浏览器截图或 activeTab 权限。重复查询复用内存图像，切换文件重新建缓存。Pro 继续使用文本，不自动切换到 Flash。图片增加输入 token 和请求体积。

## 回答风格

原文优先，沿用原文对象、术语、语气、确定性与叙述顺序；直接给出定义和明确事实。保留原文必要的否定、比较和限定，取消额外否定性澄清、读者心理猜测、强制文化拆解及没有根据的因果补全。计算和推导只在问题需要时展开。

回答采用自然中文段落，篇幅随选中内容决定，不再默认添加英文释义或固定小节。前文和选区之后约 1000 字符的上下文策略沿用现有实现。

## 选区补齐

网页和 PDF 都将选区首尾扩展到已选中英文词的完整边界，并同步原生高亮。词内撇号、连字符和型号数字保留；端点落在空白或标点时不会自动选入旁边的词。

PDF 在规范正文中补齐，因此只选中跨行断词的前半或后半，也可得到完整单词。通过原始文字项的字符映射还原高亮；PDF 页面上的排版连字符仍保持原样，弹窗标题与请求使用合并后的文字。

完整可执行系统提示词在 `src/background/prompt.ts` 的 `SYSTEM`。

## 回归验证

`scripts/inspect-pdf.ts` 使用实际 PDF.js 提取全文并输出文字项索引。
`scripts/check-reading.ts` 检查来源文字项覆盖、去重、字符映射、双栏跨页案例、上下文前缀、后文长度、图片消息和追问结构。
`scripts/check-word-selection.ts` 导出浏览器内 `run()` 检查函数，覆盖首尾补词、跨行断词、反向选择、跨行内标签、连字、复合词及高亮与请求偏移一致性。可使用项目已有 esbuild 打包后，通过 Playwright 页面执行，无需新增运行时依赖。
`scripts/browser-reading-check.js` 导出一个 Playwright 页面检查函数，在实际阅读器中选词并截获实际后台构造的 HTTP 请求。该脚本里的本地 PDF 路径是开发测试夹具，可按机器修改；Playwright 不作为扩展运行时依赖。

浏览器测试仅模拟扩展消息通道与 API 响应，复用生产阅读器、提示词组装和 HTTP 客户端；不使用真实 Key，不代表在线模型输出质量已验证。

验证资料：2201.10703v2（10 页）及 PIAD CVPR 2025 论文（10 页）。其中验证了 `augmentation` 跨栏续接、`ImageNet` 跨页续接、作者行、图 3 完整图注、`detec- / tion` 跨行选区、追问复用图像，以及换文件后页数不累加。

官方视觉格式：https://api-docs.deepseek.com/guides/vision/
